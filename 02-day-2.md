## 08:00–10:30 — Voice-agent architecture (highest-priority reading of the sprint)

1. **"Voice AI & Voice Agents: An Illustrated Primer"** — https://voiceaiandvoiceagents.com/
   (~2 hrs; the canonical free resource, by the Daily/Pipecat team). If pressed, the condensed
   notes: https://www.joeywang.blog/blog/voice-ai (~30 min) — but do the full primer if you can.
2. LiveKit, **"Voice agent architecture: STT, LLM, and TTS pipelines explained"** —
   https://livekit.com/blog/voice-agent-architecture-stt-llm-tts-pipelines-explained (25 min).
3. Softcery, **"Real-Time vs Turn-Based Voice Agents in 2026"** —
   https://softcery.com/lab/ai-voice-agents-real-time-vs-turn-based-tts-stt-architecture (20 min):
   cascaded pipeline vs speech-to-speech (OpenAI Realtime / Gemini Live) vs hybrid.

**Memorize the latency budget cold** — this is exactly the kind of number an FDE interview probes:
- Target: **~800 ms voice-to-voice** (time-to-first-audio); <500 ms feels great, >1.5 s feels broken.
- Stage budget (cascaded): VAD/turn-detection ~50–200 ms → streaming ASR partials 100–500 ms →
  LLM time-to-first-token ~350 ms+ → streaming TTS time-to-first-audio 75–200 ms → transport
  (WebRTC ~30–50 ms; PSTN/telephony adds more).
- The trick is **overlap, not speed**: stream ASR partials into the LLM, stream LLM tokens into
  TTS sentence-by-sentence; never wait for a stage to finish.
- Know: VAD (e.g., Silero) vs semantic turn-detection; **barge-in** = detect user speech during
  playback → stop TTS → cancel in-flight LLM → truncate context to what was actually heard;
  telephony (SIP/PSTN, 8 kHz) vs WebRTC (16–48 kHz) tradeoffs; why Sarvam-30B's MoE design
  (~2.4B active params) is purpose-fit for cheap low-latency voice.

**Done when:** you can whiteboard the full streaming pipeline with per-stage latency numbers
and narrate barge-in handling end-to-end.

## 10:30–12:30 — Build #2: voice pipeline + VAD from scratch

Two parts, in this order (the reported Sarvam hackathon task was literally "build a VAD"):

1. **(~45 min) Write a VAD from scratch in numpy** — no framework: read a WAV, frame it
   (20–30 ms windows, 10 ms hop), compute short-time energy + zero-crossing rate, apply an
   adaptive noise-floor threshold + hangover smoothing, output speech segments with timestamps.
   Then compare your output against `webrtcvad` or Silero on the same file. Know the vocabulary:
   sample rate, frame size, hop length, SNR, hangover. Commit to `build-2/vad/`.
2. **(~75 min) Wire a minimal Sarvam voice loop**: use Sarvam's `skills` repo voice-agents
   skill (LiveKit + Pipecat pipelines: https://github.com/sarvamai/skills) or the cookbook —
   mic/WAV in → **Saaras v3 streaming STT (WebSocket)** → Sarvam-30B chat completion →
   **Bulbul v3 streaming TTS** → audio out. Even a half-duplex turn-based version teaches you
   the real integration pain (audio formats, chunking, WS lifecycle). Commit to `build-2/agent/`.
   - Fallback if audio plumbing fights you: run the cookbook's STT-streaming and
     TTS-streaming notebooks separately and glue them file-to-file. The learning is in the
     streaming APIs, not the microphone.

## 13:00–14:30 — Kafka, SQS, and pipeline-reliability vocabulary

1. **Kafka in one sitting**: TechWorld with Nana's crash course —
   https://www.youtube.com/watch?v=B7CwU_tNYIE (~1 hr, at 1.5x ≈ 45 min; Python + Docker), or
   Confluent's Kafka 101 videos (https://developer.confluent.io/courses/apache-kafka/events/).
   Must-know words: topic, partition (ordering + parallelism unit), broker, replication factor,
   producer acks, **consumer group** (scaling + rebalancing), offset, retention, log compaction.
2. ByteByteGo quick hits (15 min): "Ultimate Kafka 101" —
   https://blog.bytebytego.com/p/ep126-the-ultimate-kafka-101-you and "Why is Kafka fast?" —
   https://blog.bytebytego.com/p/why-is-kafka-fast (sequential I/O, zero-copy, batching).
3. **SQS vs Kafka decision framework** (15 min): https://www.svix.com/resources/faq/kafka-vs-sqs/ —
   SQS = fully-managed task queue, competing consumers, no replay, per-message deletes;
   Kafka = durable log, replay, fan-out to many consumer groups, streaming; SQS FIFO for
   ordering; ops cost of self-managed brokers. (Your Azure mapping: Service Bus ↔ SQS,
   Event Hubs ↔ Kafka.)
4. **Reliability patterns** (15 min): retries with exponential backoff + jitter and a retry cap;
   poison messages → **dead-letter queue**; **idempotency keys** (at-least-once delivery means
   duplicates *will* happen); circuit breakers; backpressure (bounded queues, 429/503 +
   Retry-After). Guide: https://baxchain.com/blogs/resilient-event-driven-architecture-idempotency-retries-and-dead-letter-queues/

**Done when:** you can design "WhatsApp bot for a bank: webhook ingestion → queue → agent
workers → callback" and justify SQS vs Kafka, explain the DLQ, and place the idempotency key.

## 14:30–15:30 — AI system design drills (produce two diagrams)

Read fast (40 min): Chip Huyen, **"Building A Generative AI Platform"** —
https://huyenchip.com/2024/07/25/genai-platform.html (the step-by-step buildup: RAG → gateway →
caching → guardrails → model router → observability), then skim the interview-formatted
https://www.systemdesignhandbook.com/guides/llm-system-design/ (clarify use case/token budget →
orchestration → routing, fallbacks, cost control).

Then sketch, on paper, timed (10 min each):
1. **LIC-scale multilingual voice policy-servicing agent** (their real SBI Life deployment
   shape: 80M customers, 11 languages, nationwide): telephony/SIP ingress → streaming
   STT (code-mixed) → dialog agent w/ tool calls into core policy systems (read vs write paths,
   human handoff) → streaming TTS; queue between webhook events and workers; observability =
   transcripts + traces + eval sampling; on-prem/VPC variant for compliance; cost model
   (Sarvam prices voice ~₹1/min — what dominates? LLM tokens vs telephony vs ASR).
2. **Translation/dubbing pipeline for a media house**: ingest video → demux → time-stamped ASR
   transcript (anchor) → speaker diarization → MT with **length/verbosity control** → TTS with
   **per-utterance duration fitting** + voice consistency → re-mux with original background
   audio; human-in-the-loop QC stage; batch queue architecture. (Gotchas from the Amazon
   dubbing paper https://arxiv.org/pdf/2001.06785: prosodic alignment, isochrony, background
   preservation. Current reference: NVIDIA's content-localization blueprint, May 2026.)

## 16:30–17:30 — Mock decomp round (timed, 45 min + 15 min review)

Read the method first (10 min): the Palantir-style decomposition round is the canonical FDE
interview — https://www.coditioning.com/blog/703/palantir-swe-decomposition-interview.
Method: **ask questions before solving** (users? actions? data volumes? constraints? failure
tolerance?), name the entities and data flows, scope an explicit v1 with justification, state
failure modes and what you'd punt on, and **think out loud the whole time** — silence reads
as being stuck.

Then run one 45-min mock with an LLM playing interviewer. Prompt to use:
> "You are an FDE interviewer at an Indian AI company. Give me one ambiguous enterprise
> problem (e.g., 'A large private bank wants to automate loan-collection calls in 8 languages'
> ), then push back on my scoping with realistic constraints (compliance, legacy systems,
> latency, cost) as I think out loud. Grade me at the end on structure, questions asked,
> and v1 scoping."
