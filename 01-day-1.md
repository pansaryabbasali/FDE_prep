## 15:00–17:30 — Evals deep block (the differentiator)

Read in this order — this is a *reading* block; the practice comes tonight:

1. Hamel Husain, **"Your AI Product Needs Evals"** — https://hamel.dev/blog/posts/evals/
   (40 min). The three levels: assertions/unit tests → human + model eval → A/B.
2. Hamel + Shreya Shankar, **the Evals FAQ** — https://hamel.dev/blog/posts/evals-faq/
   (75–90 min; highest-ROI eval resource in existence). Key positions to internalize:
   **error analysis first** (look at ~20+ real traces before building any dashboard),
   binary judgments > Likert scales, LLM-judge must be *aligned to a human* (measure its
   TPR/TNR against your labels), evaluate the RAG pipeline stage-by-stage.
3. Eugene Yan, **"LLM-Evaluators (LLM-as-Judge)"** — https://eugeneyan.com/writing/llm-evaluators/
   (skim, 30 min). Judge biases: position, verbosity, self-preference; pairwise vs direct scoring.
4. 20 min tooling skim so you can name-drop accurately: Ragas (faithfulness, answer relevancy,
   context precision/recall — https://docs.ragas.io/), promptfoo (YAML-driven, red-teaming —
   https://www.promptfoo.dev/docs/intro/), LangSmith agentevals (trajectory evals), plus
   Braintrust / DeepEval / Arize Phoenix as names. Also note Sarvam's own eval repos:
   https://github.com/sarvamai/llm_wer and https://github.com/sarvamai/llm_intent_entity —
   they publicly care about ASR eval pipelines.

Then spend the last 20 min writing **your one-page evals playbook** in your own words
(this becomes your interview answer): signal vs noise, final-answer evals vs trajectory
evals (tool-call correctness, loop detection, step efficiency), offline vs online, when
LLM-judge is trustworthy, and what you'd do in week 1 at a client (error analysis on real
traces, ~20 hand-labeled examples, binary rubric, then automate).

**Done when:** you can answer "how would you evaluate a bank's multilingual voice agent?"
for 5 minutes without hesitation: task success rate per intent, WER on code-mixed speech,
tool-call correctness, latency percentiles, escalation rate, judge-vs-human agreement.

## 18:00–20:30 — Build #1: Sarvam-stack agent with an eval harness

Build a small but real thing on their APIs (pick per interest; A recommended):

- **Option A — Call analytics for a BFSI client** (mirrors Samvaad reality): take the
  `call-analytics` cookbook example (https://github.com/sarvamai/sarvam-ai-cookbook has
  sample call audio) — Saaras v3 STT (note its modes: transcribe / translate / verbatim /
  transliterate / **code-mixed**) → Sarvam chat completion (OpenAI-compatible endpoint) to
  extract intent/entities/summary as **structured JSON** → simple report.
- **Option B — Multilingual doc Q&A** (mirrors your state-gov work): Sarvam Vision doc
  parsing (async job API) → chunk → retrieve → answer with citations.

Non-negotiable additions, whichever option:
1. **Structured output** with a JSON schema and a retry-on-invalid path (know why: reasoning
   tokens can consume the budget and return `content=None` — a real documented Sarvam SDK gotcha).
2. **A tiny eval harness**: 10–15 hand-written test cases + one LLM-judge with a binary
   rubric + a pass-rate table printed at the end. This is your evals playbook made concrete.
3. Commit it to this repo (`build-1/`).

Useful shortcut: `npx skills add sarvamai/skills` — Sarvam's own condensed SDK reference
with exact signatures and gotchas (https://github.com/sarvamai/skills).

## 20:30–21:30 — Context engineering (reading; connects to your RAG scars)

1. Anthropic, **"Effective context engineering for AI agents"** —
   https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents (30 min):
   context as finite resource, compaction, structured note-taking, sub-agent isolation,
   just-in-time retrieval.
2. Lance Martin/LangChain, **"Context Engineering for Agents"** —
   https://www.langchain.com/blog/context-engineering-for-agents (20 min): the
   **Write / Select / Compress / Isolate** taxonomy — the cleanest framework to recite.
3. Manus, **"Context Engineering for AI Agents: Lessons from Building Manus"** —
   https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus (25 min):
   KV-cache hit rate as the #1 production metric (~10x cost delta), mask-don't-remove tools,
   filesystem-as-context, recitation, keep errors in context.
4. Skim Chroma's **"Context Rot"** report — https://research.trychroma.com/context-rot (15 min):
   the empirical successor to "lost in the middle" — performance degrades non-uniformly with
   input length. **Your interview hook:** you tuned retrieval and prompt ordering against
   lost-in-the-middle on a 128K-context RCA system before this had a name.
